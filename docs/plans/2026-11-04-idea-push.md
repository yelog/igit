# IDEA Push 工具窗对照实现计划

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 对照用户提供的 IDEA Push 截图，实现统一列对齐的仓库清单、带变更颜色的可折叠文件树，以及默认完整显示的右栏。

**Architecture:** 保留现有推送计划、审查与后台执行边界，只调整 Push 的只读预览、绘制和事件处理。Git 使用 NUL 分隔的 name-status 获取变更类型，树节点保留原始 PathBuf 和文件索引；可见树行与实际文件分离，避免折叠后打开错误文件。

**Tech Stack:** Rust、Ratatui TestBackend、Crossterm、系统 Git；复用现有图标、显示宽度与 IDEA 色板，无新增依赖。

---

### Task 1: 变更类型与文件树

**Files:** 新建 `src/push/files.rs`，修改 `src/push.rs`。

1. 添加目录压缩、后代计数、折叠导航、同名文件和非 UTF-8 路径测试；运行 `cargo test --locked push::files::`，确认新行为需要实现。
2. 使用 `git diff --name-status -z --find-renames` 和 `diff-tree --root --first-parent -m` 读取批次及单次提交；新目标的树文件标为新增。重命名保留来源路径，Diff 同时限定新旧路径。
3. 实现“仓库 → 内容根 → 压缩目录 → 文件”树、展开／收起及可见行到原始文件索引映射；再次运行定向测试，预期通过。

### Task 2: IDEA 仓库列与右栏

**Files:** 新建 `src/push/view.rs`、`src/push/view_tests.rs`，修改 `src/push.rs`。

1. 添加 TestBackend 测试：不同长度仓名、Unicode 宽字符、长分支、submodule、结果标记在三种图标模式下均按统一列起点绘制；窄屏控件命中保持正确。
2. 用实际字符格计算仓库、源分支、箭头、目标、待推计数和 submodule 列，超宽文本在本列截断；远端目标使用 IDEA 蓝色。
3. 文件树默认占满右栏，工具栏提供详情开关和全部收展。文件图标沿用类型色，新增／修改／删除／重命名文件名分别用绿／蓝／红／琥珀；保留文字状态。
4. 接入鼠标与 `j/k`、`h/l`、`Enter`、`d`、`Esc`；按需打开 Diff／容器摘要，关闭详情回到同一树行。运行 `cargo test --locked push::`，预期通过且现有审查和重试测试不变。

### Task 3: 实际终端验收与文档

**Files:** `README.md`、`docs/design.md`、`docs/prd.md`，必要时更新 `docs/architecture.md`。

1. 在临时本地演练仓构造多目录、增删改和重命名；用 120×36、80×24 及三种图标模式验证列对齐、目录收展、滚动、准确 Diff、选择与审查独立，取消审查后检查 Git 状态未变。
2. 运行 `cargo test --locked`、`cargo fmt --all --check`、`cargo clippy --locked --all-targets -- -D warnings`；只报告实际运行结果。
3. 更新 Push 布局、键位及验收记录。遵从用户约束，不创建 commit 或 push。

**交付：** 新增 `examples/demo-push.sh`（11 个仓库、20 个改动文件、仅本机 bare 远端）和 `docs/reference/IGit-Push-Tree.png`。Push 左栏按仓名排序，保留原本已勾选仓的浏览位置；从 Commit & Push 进入时跟随新选区。ASCII 的成功文字 `ok` 也预留完整宽度，不截掉最长仓名。

**终端验收：** Nerd Font 180×48／120×36、Unicode 与 ASCII 各 120×36／80×24，共六组伪终端走查通过。覆盖全部收展、鼠标打开 Diff、滚至末项、取消审查、复选框切换；前后逐一比较 11 仓 HEAD、index entries、工作区状态及暂存／未暂存差异，均一致。实图由实际终端字符格及颜色渲染。
