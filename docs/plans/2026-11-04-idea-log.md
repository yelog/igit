# IDEA Git Log Implementation Plan

**Goal:** Use the user's IDEA Git Log screenshot as the acceptance baseline for the native terminal Log's layout, information order, and interactions.

**Implementation scope:** Preserve real Git queries, repository isolation, and the other three work panels. Draw only with terminal characters and colors. Repositories, authors, and paths in the reference image reflect the current selection, not defaults. The stack is Rust, Ratatui, Crossterm, and system Git.

1. `src/log/model.rs`: derive default history, references, commit times, and graph lines from actual Git objects. Validate merges, repositories sharing a SHA, stash, and filters.
2. `src/log/refs.rs`: aggregate references under HEAD / Local / Remote / Tags, using path hierarchies instead of repeating a list per repository. Verify duplicate branch names, search, and expansion/collapse.
3. `src/log/inspector.rs`: show file counts by repository and directory. Order details by title, identity and time, then containing branches; preserve access to patches and parent commits.
4. `src/log.rs`, `src/shell.rs`: align top tabs, single-line filters, three-column proportions, and selection colors. Redraw commit rows and references at the right edge. Use actual rendering coordinates for button and divider hit testing; retain a single-column narrow-screen layout.
5. Check actual rendering and keyboard/mouse interactions in temporary multi-branch repositories on a wide screen, at 120×36, and at 80×24. Run `cargo test --locked`, `cargo fmt --all --check`, and `cargo clippy --locked --all-targets -- -D warnings`, and update README, interaction design, and acceptance documentation.
