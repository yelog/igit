DESIGN SPECIFICATION　/　2026.11.03

一个工作区，四个操作面。

IGit 是从 igit 或 ig 直接启动的多仓 Git 工作台。进入后，查历史、挑改动、推送、合并都在 TUI 内完成。本文配图取自可操作设计稿，键位按所在区域解释。

00 / WORKSPACE

工作区与焦点

从任意目录启动。产品应发现当前工作树、目录下的普通仓库、已初始化子模块及使用 .git 文件的 worktree；允许手动纳入或忽略。无仓库时提供“选择目录 / 重新扫描 / 退出”，不自动初始化。演示使用 atlas-web、atlas-api 和 atlas-web 的子模块 sdk-core。四张图是同一工作区的任务示例，其中合并展示单独的冲突情景。

固定区域鼠标操作键盘操作
工作区标题与 Roots点右上 Roots；选仓库，再点“应用范围”。每仓有短名及色标。r 打开；Tab 定位、Space 切换、Enter 应用，Esc 取消。
四个视图单击顶栏页签。Push 可直接打开，也可从 Commit 进入。Merge 在产品中也可从冲突文件进入。1 Log、2 Commit、3 Push、4 Merge。仅导航模式生效。
区域与控件点击所在区域获取焦点；滚轮只滚指向的列表。点击行预览，点击复选框改变执行范围。F6 / Shift-F6 遍历可见区域；Tab / Shift-Tab 遍历控件；Enter 激活。
状态栏与返回左下显示 NORMAL / INSERT / DIALOG；点“操作指南”看当前键表，点“动作”找入口。? 当前帮助，: 搜索动作；Esc 先关最近的浮层或结束编辑，q 打开退出确认。
预览 ≠ 勾选 ≠ 执行。 选中行只决定右侧看什么；复选框决定准备做什么；写操作还需审查确认。Log / Commit / Push 共用 Roots。筛掉的仓库保留勾选与草稿，但从执行集合中排除：执行集合 = 已勾选 ∩ 可见仓库 ∩ 当前可执行项。切回范围可恢复勾选。正在编辑的 Merge 文件不因筛选而关闭；其仓库被筛除时禁止应用。

三张用户参考图分别决定 Log 的左/中/右三列，Commit 的「分组 → 仓库 → 目录 → 文件」层级，以及 Push 的来源/目标列表与右侧检查区。TUI 顶栏统一切换四种任务；原 IDEA 的独立 Push 窗口在终端中使用全工作区预览。

01 / HISTORY

Log：先看轨道，再看一次提交

进入 Log ↗

初始焦点在中央提交列表，最新提交高亮。每行按参考图显示作者、日期、轨道、说明和引用；列宽不足时先截断说明，右侧详情仍保留全文。多个仓库的提交可以混排；跨仓不画父子线，同名分支可通过所属仓库区分。

任务鼠标Vim / 键盘
看历史点提交联动右侧，上下滚动中央列表。点击父 SHA 跳转；父项被筛掉时提示。图中 j/k 下/上，g/G 首/末行。
筛选左侧 Branch or tag 找分支；中央 Text or hash 查消息或哈希，叠加 Branch / User / Date / Paths。树内 / 找分支，图内 / 查提交。Enter 回列表；输入框 Esc 清除当前搜索。
导航分支点箭头收放 Local / Remote / Tags，点分支按可达历史过滤。树内 j/k 定位，h/l 收/展，Enter 激活。
查看具体差异右上点文件，双击或点 Open diff；在图中双击提交可查看默认文件的 Diff。文件区 j/k 选文件，Enter 开 Diff，Esc 关闭。
调宽拖动竖分隔线，双击恢复默认。Tab 到分隔线，左右方向键调宽；F6 跨区域。
02 / LOCAL CHANGES

Commit：挑出这次任务的改动

进入 Commit ↗

打开时默认勾选 Changes 中的文件，自建组与 Unversioned Files 不自动纳入；父节点显示全选、半选或未选。移动文件改变本地分组，保留已有勾选，不改变 Git index。光标可以停在未勾选文件上审查 Diff。

任务鼠标Vim / 键盘
预览、勾选点文件行看右侧 Diff；点框勾选，点父级复选框只切换其可见子项。树内 j/k 浏览，h/l 收/展或进出层级，Space 勾选，Enter 看 Diff。
分组点“＋ 分组”；在文件上右键、点“移动到…”或拖至目标组。未跟踪文件单列，也可直接勾选提交。n 新建组，m 选目标组；Tab、Enter 完成。
写逐仓说明点消息区的仓库名切换草稿；Amend 仅作用于正在写说明的那个仓，审查时展示被替换的提交。i 编辑，Esc 回树；Tab 到仓库选择器或 Amend。
生成 AI 草稿齿轮设置服务地址、模型、提示词。点“生成说明”，逐仓预览、编辑候选，再确认填入。Tab 聚焦齿轮 / 生成按钮，Enter 打开；Tab 切字段，Esc 取消，不动原稿。
批量提交点左下 Commit 或 Commit and Push… → 审查每仓消息、文件数和目标 → 确认。c 审查提交，P 审查提交并转 Push；消息框 Ctrl+Enter 也可审查。
提交前要能回答： 哪几个仓库？哪些文件或补丁？每个仓的消息是什么？任何仓缺少说明时，定位该仓输入框。产品中，遇到部分暂存文件需要分别查看暂存版和工作区版，并明确本次提交哪份补丁；不改变未勾选的暂存内容。当前原型按整文件演示，不模拟 index 或行级提交。

产品接入真实 LLM 时，仅发送每仓即将提交的补丁；先展示范围与模型，支持取消或改写。凭据来自环境变量或系统钥匙串。原型的配置与候选生成均留在页面内存，不请求网络。Shelf / Stash 在本稿仅展示空态。

03 / OUTGOING COMMITS

Push：每个仓推到哪里，一眼可查

进入 Push ↗

从 Commit and Push… 进入时，这批刚刚提交的仓库已勾选；直接从 Push 页签进入，示例只预选 atlas-web。选中某次提交只改变预览：实际 push 的单位是仓库的目标分支，不允许勾掉中间某个祖先提交。

任务鼠标Vim / 键盘
决定推哪些仓点仓库复选框；点箭头查看其待推提交。点击仓库看文件集合，点某次提交仅看该次文件。j/k 浏览，h/l 收/展，Space 切换所属仓，Enter 展开或转文件区。
核对目标点“编辑全部目标…”，核对每仓 source → remote:branch。底栏控制 Push tags 和 Run Git hooks。t 编辑当前仓目标；Tab 可达批量编辑、tags 与 hooks。
核对文件单击右上文件定位，双击查看关联提交；右下保留所选提交的说明与来源。F6 到文件区，j/k 下/上；Enter 打开，Esc 返回。
推送与重试点击右下 Push → 审查仓库、提交数、目标和选项 → 确认；失败后用“仅重试失败仓”。p 进入审查；Tab、Enter 确认。Tab 到重试控件，只重试当前范围内的失败项。
一次发起，逐仓反馈。 结果分为成功、失败、未执行；成功项不会被回滚或重复推送。审查弹窗有“演示远端拒绝”开关，可主动走一次部分失败流程。真实产品若缺 upstream、鉴权失败或 non-fast-forward，应指出具体仓库、目标与下一步，不自动强推。

若批次包含更新了 gitlink 的父仓，先确认依赖的子模块提交已存在于可获取的远端；必要时先提交/推送子仓，再提交/推送父仓指针。依赖不在选区时，显式提示纳入或跳过父仓，不悄悄扩大范围。

04 / THREE-WAY MERGE

Merge：两个只读来源，一个可编辑结果

进入 Merge ↗

中栏以共同基线为起点；示例含 2 处可确定的非冲突改动、2 处真实冲突。三栏按变更块垂直同步，用空行补齐不同长度。“应用非冲突变更”把两侧独立改动放入中栏，不能让真正冲突的计数下降。无法自动合并的同一行修改留给用户。

任务鼠标Vim / 键盘
切换块 / 栏顶栏上下箭头跳冲突；点某块或某栏获取焦点。点“单栏”临时放大，可随时回到三栏。[c / ]c 上/下冲突（顺序按两键），j/k 切块，h/l 换栏，z 放大。
应用安全改动点“应用非冲突变更”，查看已处理块和剩余计数。a 应用全部非冲突；u 可整步撤销。
决定一个冲突点击左沟槽 » 或右沟槽 «；也可在块工具条选“取两侧”。只改中栏，不改来源。H 取左，L 取右，b 先左后右。u 撤销。
手工编辑点“编辑结果”或双击中栏，在原处编辑当前块；点确认或取消。i 编辑，Ctrl+Enter 接受本次编辑，Esc 取消本次编辑。
完成“保存草稿”允许中途离开。全部变更处理完后“应用结果”仅确认此文件；随后单独点击“继续 Merge”。s 保存会话草稿，Shift+Enter 审查应用；Tab 到“继续 Merge”，Enter 确认。
标题必须显示真实来源。 普通 merge：左为当前分支，右为合入分支，右侧不一定是远程。rebase 时标作「新基底 / 已重放结果」和「正在重放的提交」，附短 SHA。重开已手工编辑的冲突，不用基线覆盖已有成果。

产品中的入口：Commit 树的 Merge Conflicts → 选择仓库和文件 → Resolve → 三栏编辑 → 应用文件 → 返回冲突列表或继续仓库操作。对删除/修改、二进制及子模块指针冲突，改为专用选择器，展示路径、版本或对象 SHA，不塞进文本合并器。

05 / TERMINAL BEHAVIOR

字符格、窄屏与异常状态

宽度预算

建议以 160×48 字符格为基准。Log 约 17% / 59% / 24%；Commit 约 36% / 64%；Push 约 53% / 47%；Merge 等分三栏。标题、主按钮、模式栏固定，正文各自滚动。

目标 TUI 在 120 列以下先省略次要元数据；约 80 列时以焦点区为主，保留其他区的显式切换入口。合并器可放大单栏后回到同一块。浏览器稿以桌面为优先，Log 有紧凑视图，Merge 可手动放大；超窄尺寸可横向查看。

色彩与动效

薄荷标识活动页、主动作；蓝色表示光标行；琥珀标未解决；红色配 − / 失败标签。仓库三色固定，旁边始终有名称。

目标动效集中在接受一块后中栏的短暂高亮、状态更新和完成提示，约 120 ms；不做干扰阅读的持续动画。原型尊重系统减少动效，动作菜单可关动效。终端沿用用户字体，不依赖 Nerd Font；箭头、方框提供 ASCII 替代。

条件产品交互规范
加载、无匹配先显示已就绪仓库；慢仓单独标为读取中。不移动当前行。搜索为空时给出清除过滤入口。
文件在外部变化标识预览已过期，保留分组和草稿；执行前重新核对补丁。若已开合并草稿，提示比较新磁盘版本后再应用。
编辑或执行中返回普通导航不丢草稿；文本输入不触发全局快键。真实提交/推送执行中禁用重复发起；若取消批次，仅取消尚未启动的作业。
错误与恢复仓库行内显示错误和可行动的原因，Console 给详情。只重试失败项；没有待推提交时禁用推送。外部修改、认证、hook 等失败不得显示成成功。
06 / WALKTHROUGHS

三条走查路径

  1. 历史与过滤。 启动进入 Log → j 换一条提交 → Enter 看 Diff → Esc → r 隐藏 sdk-core。验证提交、色标和仓库数同步变化，各仓之间没有伪造的连线。
  2. 跨仓提交与部分推送失败。 进 Commit → 新建分组，移动一个文件 → 保持两仓有勾选 → 生成说明并复核逐仓草稿 → Commit and Push… → 审查并确认。推送预览勾选“演示远端拒绝”，核对成功/失败列表，再只重试失败仓。
  3. 三方合并。 进入 Merge → 按 a 后仍应有 2 处冲突 → 第一处取左，第二处取右 → u 撤销最后一步 → i 改第二块并确认 → 应用文件 → 此时仍需单独继续 Merge。

建议评审者分别只用鼠标、只用键盘各走一遍。尤其观察两点：能不能分清正在看的行与即将提交的文件；点击或按下合并动作前，能不能预判中栏哪几行会变。

交付边界： 可点击稿是本地 HTML，含演示数据，刷新即复位；不会读取仓库、执行 Git、安装启动命令或调用模型。真实仓库发现、行级部分暂存、协议兼容、鉴权/签名及子模块依赖检查是产品实现约束。本稿不声称已实现这些后端能力。
