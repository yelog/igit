# IGit 产品需求与验收

适用版本：0.1.0。本文件回答「为谁做、做什么、怎样算完成」。安装和实际键位见 [README](../README.md)；四屏布局与交互细节见[设计说明](design.md)，Git 命令、状态和模块边界见[架构说明](architecture.md)。

## 产品目标

IGit 面向习惯 IntelliJ IDEA 的 Git 工具、又希望在终端内工作的开发者。用户从当前目录输入 `igit` 或 `ig`，即使这个目录自身不是仓库，也能在同一工作台里看历史、审查改动、提交、推送及解决已有冲突。鼠标用户不用先背命令，习惯 Vim 的用户也不必为了完成常用操作拿起鼠标。

典型任务：一个改动同时涉及前端、服务端和共享子模块。开发者先从三个仓库的历史找到相关提交，把两个普通仓库本次要交的文件分为一组，分别写合适的消息，一次发起提交。随后核对两个推送目标；如果只有一个仓被拒绝，保留成功结果，只处理失败仓。子模块出现冲突时，开发者能清楚地看到「哪边提供内容、哪一栏会被改写」。

## 不可破坏的操作约定

- **范围、预览、勾选、执行是四件事。** 改 Roots 只改变可见和可执行范围；筛掉的仓不能被本次提交/推送。行光标回答“正在看什么”，复选框回答“这次要操作什么”；确认页显示实际仓库、文件或目标。隐藏后再显示已选仓库，应保留本会话的选择。
- **提交版本能解释。** 选中文件已有暂存改动时提交 index 版本；没有暂存版本时才取工作区改动。审查后文件、暂存内容或 HEAD 发生影响本次计划的变化，应要求重审。未勾选的暂存项不动；部分仓成功不能说成整批失败，也不能自动回滚。真实 hook 可能改写内容，须反馈实际结果。
- **推送看可获取性。** 仓库是执行单位，查看某次提交不等于可以跳过其祖先。远端目标在审查后变化应停止；不提供强推覆盖历史。待发布历史中新增或变更 gitlink、或只更换其声明来源时，都要验证子提交可从该版本的来源获取；无法验证就提示缺哪个子仓/提交，不暗中扩大勾选范围。
- **合并不猜内容。** 两侧标识当前 Git 操作的真实版本，尤其不能在 rebase 中机械标成“本地 / 远端”。只自动处理能确定的非冲突变更；中栏可撤销，不覆盖已在外部编辑的冲突文件。适用范围为普通 UTF-8 文本（单文件最多 2 MiB）；二进制、删除/修改、特殊模式/转换等交给外部工具。
- **AI 不替用户下决定。** 发送前列明服务、仓库、所选文件和补丁大小；逐仓请求，不发送未选文件。密钥来自环境变量，不能出现在文档示例、项目配置或日志中。取消、请求失败均不得覆盖原草稿，模型返回也不会触发 commit/push。

## 当前优先级

**P0：让 Commit 面板一眼可读，同时修正预览对象。** 用户提供的 0.1.0 基线截图中，高亮行是 `Unversioned Files`，右侧却显示某一仓库的 `notes.txt`；另有“数字是计数、状态还是分支”“半选还是光标”难以分辨的问题。[当前实现](../src/commit.rs)打开预览后对容器展示范围摘要，对文件展示补丁。以下是复验条件。

| 场景 | 验收条件 |
| --- | --- |
| 选择文件、分组、仓库或目录 | 预览开启时，文件行显示该文件的准确路径与 Diff；其余节点显示该节点的范围/数量等摘要，不再把第一个后代文件当成被选对象。收起、换仓或刷新后也不得残留过期预览。 |
| 扫描多仓树 | 在同一屏能分辨分组、仓库名/分支、目录、文件、文件数及 Git 状态。仓库色块配名称；状态配符号或文字；聚焦行和勾选状态有独立标识。只读冲突项不参与父级可提交复选状态的判断。 |
| 点选和精确操作 | 点行名只浏览；点箭头只收展；点框才勾选。分别用鼠标和键盘完成“选 1 个文件、读 Diff、跨仓过滤、写说明”，两条路径应得到相同的审查清单。 |
| 长路径与不同窗口 | 在建议尺寸 120×36 和较窄的 80×24 各走一遍。优先保留文件名、勾选状态和可达的提交操作；路径截断时仍有入口读完整路径。不能仅为复制图标而要求安装专用字体。 |

**P1 候选：** 核心信息可读后再评估接收一个差异块后的短暂高亮、低色终端对比度与可关闭的动效。单文件拆分到多个分组、逐行挑选未暂存补丁、Shelf/Stash 管理和更多分支操作均未列入本轮交付；需要另立场景和验收。IGit 不承担托管服务管理、自动克隆子仓、跨仓原子提交或模型自动解决代码冲突。

## 可复现验收

在**练习工作区**执行。下列命令从源码根目录运行；脚本每次新建两个普通仓库、一个子模块及本机 bare 远端。要复验写操作，重新运行脚本获得新目录，不用重置开发者的仓库。

```sh
cargo build --locked
ws="$(sh examples/demo-workspace.sh)"
./target/debug/ig --list-roots "$ws"
./target/debug/igit "$ws"
```

| 用例／需求 | 怎么验证 | 通过标准 |
| --- | --- | --- |
| A1 启动与历史（R1、R3、R7） | 从任一入口进入 Log；在 Roots 隐藏 sdk-core，浏览并打开一条提交的 Diff，再恢复范围。 | 有三个工作树，不把 bare 远端列为第四个；筛掉仓库的提交消失，右侧详情跟随当前提交，不跨仓连父子线。 |
| A2 分组与批量提交（R3、R5、R7、R8） | 在 Commit 新建 Review；只移动一个普通仓库的 `src/config.txt`，先给两仓各写不同消息。在 Roots 隐藏另一普通仓并进入审查，取消，再恢复另一仓。选择 Commit and Push，核对两仓后确认。 | 未跟踪 `notes.txt` 默认未勾，移组不取消原勾选；隐藏仓不出现在审查中。恢复后每仓只产生一条对应消息的本地提交，并停在 Push 预览。用 `git -C "$ws/atlas-web" show --name-only -1` 等命令核对。 |

Push 文件分组复验（A11）：在[眼睛菜单](reference/IGit-Push-Group-By.png)分别切换 Directory、Repository、Module。三项默认全开，八种组合应只改变右侧的展示层级。关掉 Directory 后，三个 `system.ts` 以父目录区分；打开其中一个 Diff 再切分组，仍显示该文件的补丁。换仓或换到单条提交时保留分组选项，左侧勾选和审查范围不受影响。运行 `cargo test --locked push::` 检查分组组合、折叠导航和真实 Git 补丁。

图线复验：用相同的仓库 Paths 对照，未设置 Paths 时多个 Roots 会有额外的提交和轨道。`straight_commits_sit_on_the_rail` 验证两种终端字形的提交点都与本轨同列，兼容终端只连接真实可见的父子；`many_tips_pointing_at_one_parent` 验证 20 个直接指向共同父提交的尖端只占两条轨道；`dense_graph_keeps_one_origin` 在 80、120、180 列上验证超宽合并图的共同坐标、边缘提示及选中节点。均可用 `cargo test --locked <用例名前缀>` 单独运行。

Branch 菜单复验（A8）：在多仓工作区打开 Branch，悬停 Local 或远端展开对应分支；点星标只改收藏，重开仍保留，点名称才筛选历史。点 Favorites 取收藏分支的并集；Select... 中输入 `master..topic` 应只看到 topic 独有的提交。检查窄屏可返回、能滚到最后一个分支，点击 User 一次即可切换。运行 `cargo test --locked branch_menu` 验证。

Paths 多仓复验（A8）：在 Paths → Select... 分行输入一个目录和一个带 `[]` 的文件，结果应是其历史的并集。用 Select in Tree... 展开两个仓库，分别勾选其中一个文件及另一个仓的目录；确认前不改变日志，确认后不混入其他仓的同名路径。重开能看到原勾选，取消保留原结果。Roots 连续勾选立即更新，全部取消显示空态；切换 Log 页再返回，仓库与路径条件均保留，全局 Roots 不变。运行 `cargo test --locked paths_` 验证。

写入边界复验（A3、A4、A6）：用 `cargo test --locked <名称片段>` 分别运行 `path_scope_`、`ai_review_of_a_replaced_file`、`external_branch_switch`、`source_only_change` 和 `cannot_turn_a_non_fast_forward_into_a_push`。场景与预期结果见[修复与回归计划](plans/2026-11-04-git-write-safety.md)。

日期筛选复验（R1、R7、R8）：Date 菜单应依次显示 `Select...`、`Last 24 hours`、`Last 7 days`。分别用鼠标和键盘进入自定义范围，输入起止日期并应用；检查首尾两天都包含、非法日期和倒序范围不生效、取消保留原条件。清除日期应保留 User / Branch / Paths，切换 Log 页应恢复日期条件。运行 `cargo test --locked date_` 验证真实 Git 历史中的相对范围、未来提交排除、时间倒序祖先和日期边界，以及 48、80、120、180 列的菜单与输入命中。

Log 眼睛菜单复验（R1、R4、R7、R8）：右上角眼睛或 `o` 打开 Show / Highlight。在 Show 切换 Branch or Tag：宽屏隐藏后提交列表占满左侧，窄屏同步隐藏 Refs；用菜单或 `B` 恢复，原筛选与选中提交应保留。Columns 展开 Author、Hash、Date、GPG Signature、Graph、Message；各项即时影响日志行。检查仓库名、标签名、紧凑引用、引用位置、两种日期与三种默认高亮。选另一分支后启用 Not Cherry-Picked Commits，应降低已等价应用项亮度。关闭 Long Edges 后可点箭头跳至真实端点。默认显示作者、日期、提交图及标题，Hash 和签名默认隐藏；选项只在本次会话共享。运行 `cargo test --locked view_options` 覆盖三种图标及 48、80、120、180 列、短窗口、悬停、键鼠和页签保持，运行 `cargo test --locked log::model::presentation` 覆盖真实签名、双日期、按仓身份和 cherry 等价，同时核对 HEAD、暂存项和工作区不变。

Log 列顺序复验（A8）：在 Columns 中把 Date 移到 Author 前，再用行尾箭头把未勾选的 Hash 移到首位。日志应先显示日期、作者；勾选 Hash 后，哈希应出现在两者左侧。首末项不能绕回，移动不改勾选、不刷新历史；切换 Log 页后沿用该顺序。将 Message 移到日期前，长标题和引用只占本列；将 Graph 移到最后，箭头仍能跳到同一提交，隐藏 Graph 后不再触发。窄屏可分别关闭这两列。运行 `cargo test --locked view_options_reorder` 验证。

Log 导航与复制复验（R7、A8）：用超过一屏的历史分别在 80、120、180 列下浏览，`j/k` 应在越过当前可见边缘后才滚动；单个 `g` 不跳转，`gg/G` 到首／末条，`H/M/L` 只选择本屏顶部／中间／底部。`Ctrl-F/B` 与 `PageDown/PageUp` 按实际行数翻整页，`Ctrl-D/U` 翻半页；到首尾、空列表或缩小窗口均不越界。`yy/ym/ya` 分别复制完整 ID、含正文的消息、姓名与邮箱，连续切换不同仓提交后也应针对当前行；输入框中不触发复制，系统剪贴板不可用时明确报错。运行 `cargo test --locked navigation_` 和 `cargo test --locked ui::clipboard::` 验证导航、跨仓文本与剪贴板命令的输入／失败路径；自动测试不改写运行者的系统剪贴板。

组合键提示复验（R7、R8）：在 Log 提交列表输入 `g`，只提示后续 `g`，输入 `y` 提示 `y/m/a`；Merge 打开冲突文档后输入 `[` 或 `]`，提示后续 `c`。前缀停留 200ms 后才自动显示，199ms 时仍隐藏，无需再次输入；提前补全或取消后不能迟到弹出，改按前缀重新计时。提示显示后，方向键只改候选高亮，Enter 或点击候选与直接补全执行同一动作。Esc/Ctrl-C 收起提示且不退出、不离开文档；切面板、切焦点、菜单、输入、粘贴、失焦和缩放清除未完成序列。运行 `cargo test --locked key_sequence`，覆盖延迟边界、定时唤醒、快速补全、44×12、80×24、120×36、浮层鼠标遮挡、候选执行，以及 Merge 浏览与取消前后 HEAD、冲突 index 条目、工作区差异和文件字节保持一致。

上下文帮助复验（R7、R8）：在 Log、Commit、Push、Merge 各区域打开帮助，标题应标明当前上下文，列表优先显示当前区域的可用动作，并与 lazydb 一样默认聚焦 Search。直接输入过滤，↑/↓ 选择，Enter 执行对应的单动作快捷键；检查 gg 等组合、修饰键、面板切换、编辑光标和 Roots 弹窗内动作都进入原事件路径。输入说明或打开 Diff 后按 F1，取消帮助应恢复原草稿与焦点。选择 Commit 的审查动作后只打开审查；取消后 HEAD、真实 index 条目与工作区差异不变。运行 `cargo test --locked help_` 检查 120×36、80×24、44×12 的样式、中文编辑、候选跟随、空结果与鼠标命中。

文本选择与复制复验（A13，R7／R8）：在 120×36、80×24、44×12 中，分别在 Log 提交详情／Diff、Commit Edit commit message／Diff preview、Push Details / Diff 左键拖选，检查拖动时高亮且不复制、松开后立即复制一次并清除高亮，无需快捷键；单击、空选区和重复释放不复制。键盘全选另验 Ctrl-C、Ctrl-Insert，只读文本另验 y。核对中文、组合字符、emoji、反向与跨行选区，软换行不成为新换行，原始空行与缩进保留，分隔线与填充空格不混入文本。拖选过程中滚动仍复制正确原文，键盘选区随滚动保留；父提交哈希拖选不跳转，普通单击仍可跳转；隐藏区域／更换对象不保留旧选区。消息编辑器另验鼠标复制后在终点继续输入、Shift+方向键／Home／End、全选后输入／粘贴／删除、F2 保存和两次 Esc 取消；F1 帮助遮挡期间不复制下层，返回后恢复键盘选区。运行 `cargo test --locked ui::selection::` 和 `cargo test --locked text_selection`；测试捕获复制动作，不改系统剪贴板，同时核对勾选、HEAD、index 与工作区不变。系统剪贴板命令的字节输入／失败路径沿用 `cargo test --locked ui::clipboard::`。

完整回归运行 `cargo test --locked`。验收记录应说明终端尺寸、演示工作区和实际通过的用例；仅有静态截图不能证明预览范围、Git 写入或鼠标命中正确。
